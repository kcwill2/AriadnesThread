Executive summary

Intent

Add Rust as the third language plugin (after C++ and Scala) at full capability parity with Scala today: discovery, dependency_graph, semantic_index, load_metric, planning, extraction, rewriting, validation. The kickoff names the why: the project's core intent is multi-language support through a plugin mechanism, and rule R1 ("a foreign language can be added without friction") has never yet been exercised by a third language.

Scope

One new plugin crate crates/lang-rust; a handful of guard-legal core-spine edits (FileKind table, from_file_kind arm, one appended AggregationKind variant); one registration line; the CLI --lang closed-set growth; named enumeration amendments A1-A8; one fixture; six new milestone-named suites. Zero edits to index/graph/cluster/transform/validate/report/artifact/scheduler/ui production code.

User decisions of record (2026-10-25, do not revisit)

  • D-1 FULL PARITY ARC - all 8 capabilities, one milestone, serial handoff arc (the kickoff estimated ~5-7 hands; the planner sized it to 10).
  • D-2 SYN-CRATE PARSER - the user rejected heuristic-only correctness: parse with syn + proc-macro2 (feature span-locations mandatory) + unicode-ident, in-process and offline. Assumption A3 holds: the pipeline never invokes a Rust compile; the validator probes --version only.
  • D-3 .RS COLLISION ACCEPTED, fixtures-only - once the spine maps .rs, scanning this repo indexes its own Rust tree; accepted by the user. No test in this milestone scans the repo's own sources; benches keep running existing corpora.

Risk

The shipped risk posture is "additive and pinned": enum appends only (INV-12), byte-freeze of goldens/ar27/m00 (INV-4), C++/Scala plugin zero-diff (INV-3), capability monotonicity (INV-5). The two live costs carried honestly: the syn::__private::ToTokens import (no semver promise) and the flat-id sharing class - both deferred with dated rows, not hidden.
