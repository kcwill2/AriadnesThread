Overview

What was implemented

  • Replaced recursive DFS cycle detection with iterative Tarjan's SCC algorithm
  • Introduced CycleGroup as the single cycle currency (replacing per-path cycle enumeration)
  • Added cycle condensation for graph visualization and reporting
  • Eliminated stack overflow risk on deep include chains (100K+ nodes)

Why it was needed

  • Recursive DFS overflowed at ~2 MiB stack on 100K-node chains
  • Per-path cycle reporting produced exponential duplicates (diamond: 2 paths, real SCC: 1)
  • No condensation meant no group-level cycle analysis for UI/reporting

Key benefits

  • Stack-safe: 64 KiB default stack handles 100K nodes
  • Semantic correctness: cycle count = group count, not path count
  • Enables cycle-policy seam (informational vs blocking per package)
  • Deterministic exports across processes
