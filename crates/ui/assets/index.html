Graph Concepts

Node Colors: Headers (.h), Sources (.cpp), and Cycles each carry a distinct card color; check the legend swatches — node colors vary by theme.

Theme: The toolbar's Theme: dropdown switches Light / Dark / Dark (Grey) / Dark (Steampunk); the choice persists across reloads and exports, and standalone exported reports carry the same selector. Semantic colors (verdict spines, heat tiers, cycle red) keep their meaning in all four themes.

Edges: Complete dependencies are solid, incomplete (forward declarations) are dashed.

Closure: Number of transitive dependencies.

Degree: Connection distance from selected node.

Collateral Heat Map

Color tiers (Cold/Teal, Green, Amber, Orange, Red) show inclusion weight; noticeable fading hides unrelated nodes and heat badges (+XX col) show specific counts. The map also previews extraction as a hypothetical after-state: a violet dashed PROPOSED header node with a placeholder name and an amber dashed slimmed consumer edge.

Card verdict spines

Every reachable dependency card states its verdict on a left spine:

  • A green spine means every supplied symbol is used (needed).
  • An amber spine means partly needed.
  • A red spine means it supplies nothing and the include can go.
  • No spine means no verdict data.
  • The card fill stays pure collateral heat — a flat tier color, never a glow (glow marks selection and the root only).
Selection verdict arrows

With a file selected, its outgoing arrows state the verdict:

  • Green solid arrows (N/N used) are includes whose every supplied symbol is used.
  • Red dashed arrows (0/N used) supply nothing the selection needs and are droppable or slimmable.
  • Amber arrows (J/T used) are partially needed.
  • Grey arrows join two dependencies inside the selection's include closure: they are transitive dependencies of the selection, but no verdict is stated against it — verdicts exist only on the selection's own outgoing arrows.
  • Each card's spine and its arrow carry the same verdict.
  • These verdicts are root-relative and cover project includes only — system/stdlib headers are not analyzed or counted, so an arrow's badge never describes what the dependency itself includes.
Include Justification breakdown

The inspector's Include Justification breakdown expands the top contributing header of the selected file: the symbols it is included for, the headers those symbols need, and the collateral symbols it drags along.

Preview after extraction

With Preview after extraction (on justification rows and proposal cards) the map marks what the selected file would stop including (red dashed), what still arrives via other paths (amber dashed), and what the slim edge keeps (green); the spines hide while previewing.

  • The picture is a hypothetical after-state: a warning banner and amber dashed canvas frame say so.
  • The extracted result appears as a violet dashed PROPOSED header node with a placeholder name, its proposed edges fan out in violet, and the slimmed consumer edge turns amber dashed.
Path Illumination

Illuminates the exact include path when clicking a collateral contributor.

Hotspots
  • The 🔥 Hotspots panel (opened from the Hotspots tab on the left edge of the canvas) ranks the worst-offender files by a switchable metric (Collateral burden, Fan-in, Fan-out, Closure burden, Cycle participation).
  • Clicking a row selects the file and renders its heat map live beside the open list.
  • Clicking a row follows the metric's natural direction: Collateral burden and Fan-in switch the canvas to Consumers (←) and badge each paying file with what it pays; Fan-out and Closure burden switch to Dependencies (→); Cycle participation keeps your current Direction.
  • The 💡 Proposed extractions section below the ranking offers one-click slim-header plans that turn a hotspot into a concrete extraction.
  • Collateral is the extra symbols every consumer drags along by including a header; each card shows the drop as before → after plus the saving it buys.
  • Risk tiers (Conservative, Moderate, Aggressive) order plans by safety only; every plan the planner emits today is Conservative.
  • The consumer TU count states how many translation units include the target and need re-validation after the plan is applied.
  • Each card is a collapsed summary: plan id, target, symbol count, saving, and risk tier; click the summary to open the playbook detail, click again to collapse.
  • The playbook lists the suggested destination files with the symbols each should hold, plus the exact tool apply command — the UI never applies anything and never changes files.
  • Apply runs in the CLI: it validates the result in three tiers with automatic rollback; run tool migrate <repo-root> --plan PLAN-ID --preview first to see the consumer changes.
Restore tab

A collapsed side panel (Node Inspector or Source Code) leaves a vertical restore tab on the canvas' right edge that brings it back.

How-To Recipes

Finding & Decoupling Header Bloat
  1. Select a header.
  2. Inspect its Collateral Breakdown.
  3. Click a heavy contributor to illuminate the include path.
  4. Refactor or forward-declare.
Triage Worst Offenders
  1. Open 🔥 Hotspots from the left-edge tab.
  2. Switch the metric to rank by burden, degree, closure, or cycles.
  3. Click a row to inspect its heat map.
  4. Optionally set a directory scope chip first to rank one subtree.
Isolating Focused Subgraphs
  1. Set Direction (Dependencies / Consumers).
  2. Step Degree (1 deg, 2 deg) or use ALL-WITH-CAP with safety node caps.
Breaking Circular Dependencies
  1. Toggle Highlight Cycle.
  2. Inspect circular links.
  3. Use Pathfinder to see the loop.
