Graph Concepts

Node Colors: Headers (.h), Sources (.cpp), and Cycles each carry a distinct card color; check the legend swatches — node colors vary by theme.

Theme: The toolbar's Theme: dropdown switches Light / Dark / Dark (Steampunk); the choice persists across reloads and exports, and standalone exported reports carry the same selector. Semantic colors (verdict spines, heat tiers, cycle red) keep their meaning in all three themes.

Edges: Complete dependencies are solid, incomplete (forward declarations) are dashed.

Closure: Number of transitive dependencies.

Degree: Connection distance from selected node.

Collateral Heat Map: Color tiers (Cold/Teal, Green, Amber, Orange, Red) show inclusion weight. Noticeable fading hides unrelated nodes, and heat badges (+XX col) show specific counts. Every reachable dependency card states its verdict on a left spine: a green spine means every supplied symbol is used (needed), an amber spine means partly needed, a red spine means it supplies nothing and the include can go; no spine means no verdict data. The card fill stays pure collateral heat — a flat tier color, never a glow (glow marks selection and the root only). The inspector's Include Justification breakdown expands the top contributing header of the selected file: the symbols it is included for, the headers those symbols need, and the collateral symbols it drags along. With Preview after extraction (on justification rows and proposal cards) the map marks what the selected file would stop including (red dashed), what still arrives via other paths (amber dashed), and what the slim edge keeps (green); the spines hide while previewing. The picture is a hypothetical after-state: a warning banner and amber dashed canvas frame say so, the extracted result appears as a violet dashed PROPOSED header node with a placeholder name, its proposed edges fan out in violet, and the slimmed consumer edge turns amber dashed. With a file selected, its outgoing arrows state the verdict: green solid arrows (N/N used) are includes whose every supplied symbol is used, red dashed arrows (0/N used) supply nothing the selection needs and are droppable or slimmable, and amber arrows (J/T used) are partially needed. Grey arrows join two dependencies inside the selection's include closure: they are transitive dependencies of the selection, but no verdict is stated against it — verdicts exist only on the selection's own outgoing arrows. Each card's spine and its arrow carry the same verdict. These verdicts are root-relative and cover project includes only — system/stdlib headers are not analyzed or counted, so an arrow's badge never describes what the dependency itself includes. A collapsed side panel (Node Inspector or Source Code) leaves a vertical restore tab on the canvas' right edge that brings it back.

Path Illumination: Illuminates the exact include path when clicking a collateral contributor.

Hotspots: The 🔥 Hotspots panel (opened from the Hotspots tab on the left edge of the canvas) ranks the worst-offender files by a switchable metric (Collateral burden, Fan-in, Fan-out, Closure burden, Cycle participation). Clicking a row selects the file and renders its heat map live beside the open list. The 💡 Proposed extractions section below the ranking offers one-click slim-header plans that turn a hotspot into a concrete extraction.

How-To Recipes

Finding & Decoupling Header Bloat: Select a header -> inspect Collateral Breakdown -> click a heavy contributor to illuminate the include path -> refactor or forward-declare.

Triage Worst Offenders: Open 🔥 Hotspots from the left-edge tab -> switch the metric to rank by burden, degree, closure, or cycles -> click a row to inspect its heat map -> optionally set a directory scope chip first to rank one subtree.

Isolating Focused Subgraphs: Set Direction (Dependencies / Consumers) and step Degree (1 deg, 2 deg) or use ALL-WITH-CAP with safety node caps.

Breaking Circular Dependencies: Toggle Highlight Cycle -> inspect circular links -> use Pathfinder to see the loop.
